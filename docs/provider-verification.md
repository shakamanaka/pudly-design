## Final source findings

The earlier generic Claude CLI classification gap is corrected for typed structured results. `ClaudeCodeAdapter.responseBody` now requires the documented success envelope (`type=result`, `subtype=success`, `is_error=false`, object `structured_output`) and rejects error-shaped or incomplete output. `claudeStructuredFailure` maps typed `authentication_error`, `billing_error`, `rate_limit_error`, and `error_max_turns` to safe categories/codes; provider prose and stderr are not exposed. Unknown structured errors and nonzero exits without a recognized typed error still fail safely as generic `provider.cli_failed`, which `classifyFailure` records as transport. That generic outcome is appropriate when there is no trustworthy structured category.

Model and effort support are rejected before provider launch by catalog/preflight validation (`provider.effort_unsupported` and provider selection diagnostics). A stale or newly unsupported model reported by Claude at runtime does not currently get a dedicated mapping: an unrecognized structured API subtype (such as a generic invalid-request type) remains safe `provider.cli_failed`/transport. The fixture suite explicitly covers the three typed auth/billing/rate categories and execution-limit result. It does not establish every upstream invalid-request subtype as model-specific, and the implementation correctly avoids inferring a model error from raw provider prose. Keep this as a disclosed adapter limitation unless a stable documented typed identifier is added; it does not invalidate preflight rejection for unsupported selections.

The CLI transport also now preserves the child process-group ID independently of parent close and schedules SIGKILL after grace, so a descendant surviving SIGTERM cannot remain active. The new resistant-grandchild fixture verifies this regression.

No real Claude or MiniMax credentials were used, so both providers remain live-unverified as allowed by the plan. The Codex real run covers only its selected model and effort; the Codex adapter has safe quota/unsupported mapping, but no paid failure request was made during acceptance.

## Claude isolation source verification

The installed Claude Code CLI help (read-only `claude --help`; no provider run) documents that `--restricted` ignores user/project/local settings and confines file tools to working directories, while `--safe-mode` disables customizations including user/project instruction sources; authentication remains usable normally. The adapter additionally runs in a disposable directory, disables all tools, denies MCP tools, and disables session persistence. `--bare` is used only for API-key auth because the CLI documents that it disables OAuth/keychain auth. Fixture assertions confirm the intended flags, environment and cwd. This supports the subscription isolation claim at the CLI contract level, subject to the documented managed-policy exception; it is not live Claude acceptance.
