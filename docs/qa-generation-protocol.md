# Generation protocol reliability

## Typed wire format

The CLI response is `{ "operations": [<operation object>...], "summary": "..." }`. Each operation is a JSON object constrained by a capability-filtered, closed schema. Operation strings containing encoded JSON are rejected. Every object requires its declared keys and rejects extra keys; operation kinds and fields use separate `anyOf` branches. The wire schema uses only Structured Outputs-supported constructs: object, array, string, number, integer, boolean, enum, `anyOf`, `$defs`/`$ref`, and supported validation keywords. The installed Codex CLI was `codex-cli 0.154.0`; the CLI help confirms `exec --output-schema <FILE>`. OpenAI's [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) documents the supported subset and definitions/references.

With all six operation capabilities negotiated, the generated schema is 11,678 bytes and uses 32 definitions. A provider-schema regression assertion keeps it below 13,000 bytes, reducing repeated nested layout/style declarations while retaining structural constraints.

## Creation proposal and deterministic lowering

`node.create` proposals carry the original stable node `id`, `name`, `kind`, required `pageId`, explicit `parentId` (string or `null`), zero-based `index`, nullable `layout` and `style`, and explicit `visible`, `constraints`, and `responsive` values. A null parent inserts at the supplied page root; a string parent inserts under that node while preserving the supplied page ID. The transaction rejects a parent on another page. The only advertised create kinds are `frame`, `group`, `text`, and `component-instance`, matching the current rendered creation set. Text additionally requires `text` and nullable `textStyle`. Component instances additionally require `componentId`, `variantId`, `propertyOverrides`, `nodeOverrides`, and `slotChildren`. Dictionaries cross the schema boundary as closed arrays of `{key,value}` pairs because provider-compatible arbitrary-key JSON objects cannot be described with closed object properties. Duplicate keys and `__proto__`, `prototype`, or `constructor` keys are rejected.

Null is used only as a typed omission marker. Compilation maps null layout to a deep clone of domain `DEFAULT_LAYOUT`, null style to `{}`, and null text style to `{}`. It initializes `childIds: []`; visible, constraints, and responsive data remain explicit and are preserved. For nullable optional fields inside supplied layout/style/text-style/constraint/responsive values, null lowers to omission. The compiler keeps supplied IDs, values, and placement exactly; it does not derive IDs, move nodes, fix invalid values, infer page/parent relationships, or create content. Domain transaction validation still checks document-dependent placement, scope, graph invariants, component references, and token compatibility.

Position is accepted only as `layout.position: {x,y}` (or `null`) and is checked as finite numeric coordinates. A top-level `position` field, positions on other objects, unsupported node kinds, fields from another kind, unknown keys, malformed arrays, and invalid operation shapes fail protocol parsing before batch validation. Other operations retain their existing operation payload shape as typed JSON objects; `node.move` uses a required nullable `parentId`, lowered to an omitted domain field for page-root placement.

## Error and evidence boundary

`parseAgentResponse(value, capabilities)` keeps the adapter contract and returns the existing `CodingAgentResponse`. Structural failures throw `AgentProtocolError` with a stable code and safe message. The Codex adapter maps known protocol codes to actionable safe diagnostics. This parser verifies structure and negotiated capability only; it does not claim that an operation is semantically applicable or that a real design has been generated. The protocol and CLI fixture tests verify adapter behavior only. Real prompt-to-design acceptance requires the separately coordinated real Codex plus browser run.

Focused verification: `tests/adapters/codex-protocol.test.ts` and `tests/adapters/codex-cli-adapter.test.ts` cover closed typed schemas, schema size, deterministic defaults, stable IDs and placement, nested position, malformed and unknown fields, unsupported kinds/capabilities, nullable lowering, duplicate/prototype-sensitive dictionary keys, and existing CLI process-fixture behavior.
