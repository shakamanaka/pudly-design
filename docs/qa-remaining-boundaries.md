# Remaining boundary review

This is a bounded, read-only QA review of the source paths left outside the earlier export audit. It is not a Codex Security scan or a certification. I reviewed the active `design-engine-foundation` contracts and traced the listed behavior through current source and existing tests. No production code or tests were changed for this review.

## Finding

**Figma component-template fidelity reporting does not enumerate all template features.** The exporter reports template constraints, shadow, responsive behavior, assets, and text typography individually, then reports the definition broadly as degraded. It does not emit entries for other template-level features it maps, such as name/visibility, layout and sizing, fill/text color, opacity, radius, text content/alignment, or vector geometry. The plugin runtime applies several of these values, but the result has no per-feature status for them. This falls short of the export contract that each encountered feature/node receive a fidelity status. The broad `component-definition:<id>` entry reports flattening/reuse loss, but does not identify the mapping status of those specific template features.

Evidence: [export-architecture spec](../openspec/changes/design-engine-foundation/specs/export-architecture/spec.md:14) requires per-feature reporting; [Figma fidelity generation](../src/adapters/export/figma.ts:201) has the incomplete template-feature enumeration; [Figma mapping runtime](../src/adapters/export/figma.ts:270) applies several fields. The Vue exporter already has a broader per-template matrix at [vue.ts](../src/adapters/export/vue.ts:449), which can inform the follow-up. Add a component-template Figma test that asserts fidelity entries for every mapped or lost template feature, including an explicit status/fallback for unsupported ones.

## Reviewed boundaries with no confirmed defect

- Browser UI data and error/context surfaces: `src/App.vue`, `src/ui/components/CanvasNode.vue`, `src/ui/components/LayerTreeNode.vue`, `src/ui/components/InspectorPanel.vue`, and `server/router.ts`. User-controlled labels, prompts, diagnostic messages, and context JSON render through Vue interpolation/text nodes; no `v-html`, `innerHTML`, or DOM HTML injection sink was found. Router errors serialize JSON, and API request bodies are bounded and shape-checked.
- Generated Vue output: `src/adapters/export/vue.ts`. Design content is emitted in JSON data files and rendered with Vue interpolation; generated node content is not inserted with `v-html`. Existing coverage includes hostile script/HTML text (`tests/export/export-audit.test.ts`, `tests/export/vue-export.test.ts`) and portable bundle paths (`tests/export/vue-bundle.test.ts`).
- Figma generated code: `src/adapters/export/figma.ts`. Payload JSON escapes `<` and Unicode line separators before insertion into the static plugin script; vector path data is escaped for SVG attribute context. Existing export audit executes the generated script with hostile text using a fake Figma runtime.
- Tokens and components: `src/domain/document.ts`, `src/domain/component-validation.ts`, `src/domain/validation-utils.ts`, and `src/domain/design-system-policy.ts`. Document validation uses a token `Map`, own-entry checks, shape validation, and dangerous-key rejection; component resolution uses own-property lookup. Existing tests cover token categories, property/variant validation, malformed component data, and opaque IDs. Some downstream render helpers use bracket lookup after the service/exporter has validated the document; I found no demonstrated bypass from that pattern in the reviewed call paths.
- Runtime request parsing: `server/router.ts` enforces body size, JSON content type, exact allowed keys, typed values, and route-specific ID syntax; domain operation/run parsers perform semantic validation. The existing local-router suite covers the request boundary. No accepted unknown-field path was identified in the reviewed routes.
- ZIP/native boundary: `src/adapters/export/bundle.ts` checks relative artifact names, path segments, duplicate/case-colliding paths, reserved report name, and canonical base64 before packaging. Existing tests cover traversal, absolute/drive paths, backslashes, NUL, prototype names, duplicates, and invalid encoding. Native export (`src/adapters/export/native.ts`) emits validated JSON and has semantic round-trip tests. I found no native ZIP importer or archive-unpacking path in this source tree; importing externally supplied native/ZIP files is therefore outside the implemented boundary reviewed here.

## Discovery and limits

The configured Codebase MCP index was ready at the current repository root when queried. Semantic searches surfaced the router, UI, component validation, and exporter symbols, and I checked each relevant path directly against the checkout. The index reported two parser-partial test ranges, neither of which was used as sole evidence. This review did not execute tests, a browser session, a Figma session, or arbitrary imported archive handling. Root independently reported the production browser checks passing; that result was not used to infer coverage of this review's Figma template fidelity gap.

## Resolution on resume

Template per-feature reporting is corrected and independently checked against generated importer execution, including subsequent instance/unused-definition/type-mapping corrections. See docs/qa-figma-fidelity-verification.md and tests/audit/figma-fidelity-claims.test.ts. No recorded finding from this review remains open.
